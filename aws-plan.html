Executive Strategy: The Dual-Layer Cloud & AI Assessment Model
AWS architectures running Generative AI span both traditional cloud infrastructure (IAM, VPC, S3, KMS) and AI-specific services (Amazon Bedrock, Bedrock Guardrails, Bedrock Agents, Amazon Q Business). Evaluating security requires uniting deterministic cloud infrastructure audits (IAM least privilege, VPC PrivateLink, S3 bucket policies) with probabilistic LLM red teaming (Promptfoo adversarial attack batteries).

1. Testing Boundary: Promptfoo vs. AWS Cloud Infrastructure Auditing

Workstream A: Cloud Infrastructure & IAM Deterministic

Validates Service Control Policies (SCPs), IAM least privilege, VPC PrivateLink endpoints, and S3 bucket encryption. Output: Zero CIS Benchmark violations.

Automates adversarial attacks against Amazon Bedrock endpoints, Bedrock Guardrails, and Agents using Promptfoo. Output: Guardrail interception rate & vulnerability metrics.

Workstream A: AWS Cloud Infrastructure & Data Hardening

Deterministic Controls: IAM Identity Center, VPC PrivateLink, S3 Storage & KMS
Phase: 1, 2 & 3
Standards: CIS AWS Foundations • AWS Well-Architected GenAI Lens

Phase 1: IAM Governance, Service Roles & Organization SCPs

Service Control Policies (SCPs)
  • Model Region Restrictions: Enforce organization-level SCPs that deny bedrock:* API access outside designated sovereign regions.
  • Model Enablement Gate: Restrict bedrock:PutModelInvocationLoggingConfiguration and model access subscriptions to Cloud SecOps roles only.
Bedrock Execution Service Roles
  • Least Privilege Roles: Ensure Bedrock Agent execution roles can invoke only specifically mapped Lambda functions, not lambda:InvokeFunction on *.
  • PassRole Boundary: Restrict iam:PassRole to prevent developers from passing high-privilege roles to Bedrock agents or clusters.

Phase 2: VPC Network Isolation & S3 Knowledge Base Storage

Ensure that all model training, inference, and RAG document retrievals transit isolated networks without traversing the public internet:

  • VPC Interface Endpoints (AWS PrivateLink): Verify that private subnets communicate with Amazon Bedrock via com.amazonaws.<region>.bedrock-runtime and com.amazonaws.<region>.bedrock VPC endpoints.
  • S3 Bucket Policies & Condition Keys: Lock down S3 buckets hosting Bedrock Knowledge Bases using condition keys enforcing TLS 1.2+ and restricting reads strictly to the Bedrock Service Principal:
# S3 Bucket Policy snippet: Restrict access to Bedrock Service Principal and VPC Endpoint only { "Effect": "Deny", "Principal": "*", "Action": "s3:*", "Resource": ["arn:aws:s3:::bedrock-kb-docs", "arn:aws:s3:::bedrock-kb-docs/*"], "Condition": { "StringNotEquals": { "aws:sourceVpce": "vpce-0123456789abcdef0" } } }
  • KMS Customer Managed Keys (CMK): Verify that all custom fine-tuned model weights, OpenSearch Serverless vector indices, and S3 Knowledge Base documents are encrypted with CMKs with automated rotation enabled.

Phase 3: Model Invocation Logging, CloudTrail & Forensics

Audit logging is legally mandatory for regulated AI workloads. Verify invocation logging is active and tamper-proof:

  • Bedrock Model Invocation Logging: Ensure full request and response bodies, metadata, and images are logged to a dedicated, encrypted S3 audit bucket and CloudWatch log group.
  • CloudWatch Log Metric Filters & Alerts: Create alerts in Amazon GuardDuty and CloudWatch for invocation spikes, unauthorized model access errors (HTTP 403), or Guardrail block events.
# AWS CLI Audit: Verify that Model Invocation Logging is enabled in the current region: aws bedrock get-model-invocation-logging-configuration --region us-east-1

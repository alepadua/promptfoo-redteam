Executive Strategy: Google Cloud GenAI & Perimeter Defense
Deploying generative AI on Google Cloud revolves around Vertex AI (Gemini Foundation Models, Model Garden, Agent Builder, Search) backed by native data and networking services (Cloud Storage, BigQuery, VPC Service Controls). Robust security requires marrying deterministic cloud perimeter controls (VPC-SC data exfiltration defense, Workload Identity, CMEK) with probabilistic LLM red teaming (Promptfoo adversarial attacks).

Workstream A: Google Cloud Infrastructure & Data Perimeter

Deterministic Controls: VPC Service Controls, IAM Workload Identity, CMEK & Logging
Phase: 1, 2 & 3
Standards: CIS GCP Benchmark • Google SAIF Framework

Phase 1: IAM Governance, Service Accounts & Organization Policies

Organization Policy Constraints
  • Disable SA Key Creation: Enforce constraints/iam.disableServiceAccountKeyCreation to prevent long-lived JSON credentials.
  • Restrict Resource Locations: Enforce constraints/gcp.resourceLocations to ensure Vertex AI models and GCS buckets stay in sovereign regions.
Vertex AI IAM Least Privilege
  • Role Separation: Disallow granting roles/aiplatform.admin broadly. Restrict applications to roles/aiplatform.user.
  • Workload Identity Federation: Mandate Workload Identity Federation for GKE clusters, Cloud Run, and CI/CD pipelines accessing Vertex AI.

Phase 2: VPC Service Controls (VPC-SC) & Private Service Connect (PSC)

VPC-SC creates an impermeable data perimeter around Google Cloud managed services, preventing unauthorized exfiltration:

  • Service Perimeter Definition: Ensure the VPC-SC security perimeter encloses both aiplatform.googleapis.com (Vertex AI) and storage.googleapis.com (Cloud Storage).
  • Data Exfiltration Boundary Test: Attempt copying a dataset or calling a Vertex AI endpoint from an identity located outside the perimeter. The request must be rejected with VPC_SERVICE_CONTROLS_PERIMETER_DENIAL:
# CLI Verification: Query Vertex AI endpoint from an unapproved IP/VPC; must fail with perimeter denial: curl -s -X POST -H "Authorization: Bearer $(gcloud auth print-access-token)" \ -H "Content-Type: application/json" \ https://us-central1-aiplatform.googleapis.com/v1/projects/PROJ/locations/us-central1/endpoints/EP:predict \ -d '{"instances": []}' | grep -E '"VPC_SERVICE_CONTROLS_PERIMETER_DENIAL"|"status": 403'
  • Private Service Connect (PSC): Verify that Vertex AI online prediction endpoints are deployed with PSC enabled, ensuring inference traffic stays strictly on private IP addresses.

Phase 3: CMEK Encryption, Cloud Audit Logs & Security Command Center

Ensure that all model weights, datasets, and embeddings are protected with customer-managed encryption and logged:

  • Customer-Managed Encryption Keys (CMEK): Audit Cloud KMS configuration; verify CMEK is enabled with automated key rotation (90 days) for Vertex AI Datasets, Feature Store, and Vector Search indices.
  • Cloud Data Access Audit Logs: Enable DATA_READ and DATA_WRITE audit logging for Vertex AI to record all prompt invocations and model predictions in Cloud Logging.
# gcloud Audit: Confirm Data Access Audit Logs are enabled for Vertex AI (aiplatform.googleapis.com): gcloud projects get-iam-policy my-genai-project --format=json | grep -A 10 "aiplatform.googleapis.com"

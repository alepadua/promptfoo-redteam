Executive Strategy: The Dual-Layer Assessment Model
Databricks is both an analytical data lakehouse hosting enterprise crown jewels and a generative AI platform serving Foundation Models, RAG apps, and agentic Text-to-SQL (Genie). A secure architecture requires combining deterministic infrastructure audits (Identity, VPC Network, Storage, Unity Catalog RBAC) with probabilistic LLM red teaming (Promptfoo).

1. Testing Boundary: Promptfoo vs. Infrastructure Testing

To ensure total coverage and prevent blind spots, assessment techniques are strictly divided by evaluation mechanism:

2. Architecture & Testing Flow

Workstream A: Infrastructure & Data Deterministic

Evaluates binary access policies, network perimeters, IAM token lifecycles, and Unity Catalog dynamic column masking. Output: Pass/Fail policy compliance.

Workstream B: GenAI Red Team Probabilistic

Executes dynamic, multi-turn jailbreaks, prompt extractions, and SQL injections against Databricks AI Serving and Genie Spaces. Output: Vulnerability rate & guardrail efficacy.

Workstream A: Infrastructure & Data Lakehouse Hardening

Deterministic Controls: Network, Identity, Runtime Isolation & Unity Catalog
Phase: 1, 2 & 3
Standards: CIS Databricks Benchmark • ISO 27001

Phase 1: Perimeter Network & Identity Governance

Network Ingress & Egress Isolation
  • IP Access Lists: Verify workspace enforces strict CIDR allowlisting for Web UI and API. Test connection from unlisted IP; must yield HTTP 403 Forbidden.
  • No Public IPs: Verify data plane worker nodes run in customer-managed private subnets with no_public_ips = true.
  • PrivateLink Endpoints: Ensure Control Plane ↔ Data Plane and Data Plane ↔ Cloud Storage transit over dedicated private endpoints.
Identity, SCIM & Token Management
  • SSO & MFA: Mandate SAML 2.0 / OIDC SSO via Okta / Entra ID with conditional access policies.
  • PAT Token Policy: Restrict Personal Access Token max lifetime to ≤ 90 days. Enforce Service Principals for all CI/CD and automation.
  • SCIM Auto-Deprovisioning: Validate that offboarded users immediately lose workspace access via automated directory sync.

Phase 2: Compute Runtime & Cloud Credential Isolation

Prevents multi-tenant cluster breakouts and unauthorized access to cloud provider instance credentials:

  • Cluster Access Mode: Restrict interactive multi-user clusters to Shared Access Mode with Unity Catalog enforcement. Disallow user-level container customization or sudo privileges.
  • Cloud Metadata Service (IMDS) Hardening: Verify worker nodes block access to cloud metadata endpoints to prevent stealing the cluster's IAM role:
# Execute inside a standard user notebook on a Shared Unity Catalog cluster: %sh curl -s -m 2 http://169.254.169.254/latest/meta-data/ || echo "IMDS_PROPERLY_BLOCKED"
  • Secrets Redaction & Scope ACLs: Audit secret scopes using Databricks CLI. Validate that dbutils.secrets.get() automatically masks keys as [REDACTED] in driver logs and notebook outputs.

Phase 3: Unity Catalog Data Governance & Storage Security

Unity Catalog is the primary data perimeter. Direct cloud storage bypass must be mathematically prohibited:

  • Dynamic Column Masking: Confirm sensitive columns (e.g. salary, SSN, email) are defined with MASKED WITH routines, displaying hashed/truncated values to non-privileged personas.
  • Row-Level Filtering: Validate row filter functions restrict access based on user session properties (e.g. IS_ACCOUNT_GROUP_MEMBER('finance_team')).
  • Storage Credential Bypass Test: Attempt direct storage reads using cloud paths. Access must be rejected:
# Attempting direct bucket read without Unity Catalog External Location privileges must fail: try: df = spark.read.load("abfss://lakehouse@storage.dfs.core.windows.net/raw/finance/") except Exception as e: print("SUCCESSFULLY_DENIED_DIRECT_STORAGE_BYPASS")
